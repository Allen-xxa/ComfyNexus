### 示例一：资产库批量收藏会把已收藏项取消

| 字段 | 内容 |
|---|---|
| 标题 | 资产库批量收藏会把已收藏项取消 |
| 编号 | BUG-001 |
| 严重程度 | S2 |
| 优先级 | P1 |
| 模块 | 资产库 |
| 环境与版本 | Windows 11 专业工作站版；应用版本 v1.x（本地工作区）；Python 3.12.3；后端 127.0.0.1:5000；非打包运行 |
| 复现率 | 必现 |
| 前置条件 | 临时库目录中有 3 个资产，其中资产 A 已收藏；进入资产库批量模式 |
| 复现步骤 | 1. 批量选中 A、B、C 三个资产<br>2. 点击批量操作条「收藏」<br>3. 查看三个资产的收藏图标与收藏分类计数<br>4. 刷新页面后再次查看 |
| 实际结果 | A 由已收藏变为未收藏，B、C 变为已收藏；收藏计数为 2（预期 3）；再次点击「收藏」时三个状态全部反转 |
| 期望结果 | 批量收藏为幂等操作：无论原状态如何，执行后三项均为已收藏，计数为 3；重复点击不取消收藏 |
| 影响范围 | 所有使用批量收藏的用户；已收藏资产会被误取消，需逐个重新收藏；无数据删除风险，但会造成收藏状态丢失 |
| 证据 | `source-code/data/gallery/assets.json` 操作前后 `isFavorite` 对比；操作前后收藏计数截图；前端调用记录显示对每个 id 调用 `gallery_toggle_favorite` |
| 首次出现版本 | 待确认（当前基线可复现） |
| 是否回归 | 未知 |
| 关联用例 | TC-GAL-020 |
| 修复验证方式 | 重新执行 TC-GAL-020：选中 1 个已收藏 + 2 个未收藏，点击一次后 3 个 `isFavorite=true`，计数 +2；连续点击两次仍全部为已收藏。回归 TC-GAL-021、TC-GAL-022 |
| 状态 | 新建 |
| 记录人 / 日期 | Agent / 2026-11-04 |

**根因备注（供修复参考）**

- 前端 `AssetBatchToolbar.tsx` 对选中项逐个调用 `toggleFavorite`，非幂等。
- 后端已有 `gallery_batch_favorite(asset_ids, favorite)`，前端未使用。
- 修复方向：批量收藏调用批量接口并显式传 `favorite=true`，不要循环 toggle。

### 示例二：资产 scheduler 字段保存后丢失

| 字段 | 内容 |
|---|---|
| 标题 | 资产 scheduler 字段保存后丢失，详情无法显示调度器 |
| 编号 | BUG-002 |
| 严重程度 | S2 |
| 优先级 | P0 |
| 模块 | 资产库 |
| 环境与版本 | Windows 11 专业工作站版；应用版本 v1.x（本地工作区）；Python 3.12.3；非打包运行 |
| 复现率 | 必现 |
| 前置条件 | 有一张含 workflow 的 PNG，workflow 中 scheduler=`normal`；库路径指向临时目录 |
| 复现步骤 | 1. 执行增量扫描导入该 PNG<br>2. 打开资产详情，查看 sampler/scheduler 区域<br>3. 退出应用后重启<br>4. 用文本编辑器打开 `source-code/data/gallery/assets.json` 搜索 `scheduler` |
| 实际结果 | 详情中 scheduler 为空；重启后仍为空；`assets.json` 中该资产没有 `scheduler` 字段（其他参数如 steps/cfg 正常） |
| 期望结果 | 详情显示 scheduler=`normal`；重启后保持；`assets.json` 中存在 `scheduler` 字段且值正确 |
| 影响范围 | 所有含工作流的图片/视频资产；参数展示不完整，用户无法据资产复现生成参数；属于静默数据丢失 |
| 证据 | `assets.json` 片段（缺 `scheduler`）；详情面板截图；扫描日志中 workflow 解析成功 |
| 首次出现版本 | 待确认（当前基线可复现） |
| 是否回归 | 未知 |
| 关联用例 | TC-GAL-033 |
| 修复验证方式 | 重新执行 TC-GAL-033：扫描含 scheduler 的 PNG，重启后详情显示 `normal`，`assets.json` 存在该字段；回归 TC-GAL-002、TC-GAL-023 |
| 状态 | 新建 |
| 记录人 / 日期 | Agent / 2026-11-04 |

**根因备注（供修复参考）**

- `source-code/backend/src/gallery/models.py` 的 `Asset.to_dict()` 未输出 `scheduler`，而 `from_dict()` 会读取，导致「读得到、存不下」。
- 扫描时对象内有值，但整份 `assets.json` 重写后字段被丢弃。
- 修复方向：在 `to_dict()` 补 `scheduler`，并检查 `_create_asset`/`_update_asset` 与增量扫描 `update_dict` 三处一致性；补一条序列化往返单测。
