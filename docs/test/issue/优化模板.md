### 示例一：影院模式离开页面后全局侧边栏不复位

| 字段 | 内容 |
|---|---|
| 标题 | 影院模式离开资产库后全局侧边栏不复位 |
| 编号 | OPT-001 |
| 类型 | 体验 |
| 现状与痛点 | 在影院模式中通过舞台开关隐藏左侧导航、顶部筛选或右侧详情后，如果直接点击侧边栏跳转到其他页面（不按 Esc、不走关闭按钮），全局 chrome 状态仍保持隐藏；进入设置/提示词库后左侧导航缺失，用户需要回到资产库手动点「显示全部」才能恢复。对不熟悉影院模式的用户，表现为「侧边栏消失」。 |
| 期望效果 | 离开资产库路由时自动恢复全局侧边栏与顶部区域；返回资产库时处于非影院、非全屏状态；无论通过 Esc、关闭按钮还是路由跳转，结果一致。 |
| 涉及模块与文件 | `source-code/frontend/src/pages/AssetLibraryPage.tsx`（影院状态与 `showAllChrome` 调用）、`source-code/frontend/src/stores/useChromeStore.ts`（全局 chrome 状态）、`components/layout/MainLayout.tsx`（路由挂载/卸载时机） |
| 影响面与风险 | 只改前端状态复位，不涉及数据格式与桥契约；风险是其他页面也依赖 `useChromeStore`，复位范围过大可能影响工作区全屏；回滚只需还原页面卸载逻辑。 |
| 验收标准 | 1. 影院内隐藏侧栏后直接点击「设置」，设置页侧栏立即可见<br>2. 返回资产库时为普通网格视图，侧栏与筛选可见<br>3. 在工作区等其他页面使用全屏时，不受资产库复位逻辑影响<br>4. `Esc` 退出影院的行为保持不变 |
| 优先级依据 | 影响所有使用影院模式的用户；发生频率中等；有替代路径（回资产库手动恢复），但容易造成「界面坏了」的误解。 |
| 是否阻塞发版 | 否 |
| 关联用例 | TC-GAL-025、TC-GAL-026 |
| 关联问题 | 无 |
| 状态 | 新建 |
| 记录人 / 日期 | Agent / 2026-11-04 |

**实现建议**

- 在资产库页面卸载或路由变化时统一调用 `showAllChrome()`，而不是只在影院关闭按钮里调用。
- 如果 `useChromeStore` 还被其他全屏场景复用，增加「按页面作用域」的恢复，避免全局复位误伤。

### 示例二：停止扫描无法及时中断长任务

| 字段 | 内容 |
|---|---|
| 标题 | 停止扫描无法及时中断长任务 |
| 编号 | OPT-002 |
| 类型 | 可维护性 / 健壮性 |
| 现状与痛点 | 大型库（数百至上千文件）扫描时点击「停止」，按钮状态可能长时间不变，进度继续增长；用户只能等待扫描自然结束。根因是 `stop_scan()` 设置的是类属性/类级标志，而扫描循环读取实例属性，两者不同步。对用户表现为「停止按钮没反应」；对维护者表现为取消语义分散在前后端，难以测试。 |
| 期望效果 | 点击停止后 2 秒内扫描进入停止态，进度不再增长；已处理的资产保留、未处理的文件不写入；可以立即重新启动扫描；前后端取消状态通过同一接口可查询、可断言。 |
| 涉及模块与文件 | `source-code/frontend/src/stores/useAssetStore.ts`（`stopScan`、`pollScanProgress`）、`source-code/backend/src/gallery/scanner.py`（扫描循环与取消标志）、`bridge/api.py`（`gallery_stop_scan`）、`gallery/controller.py`（扫描状态） |
| 影响面与风险 | 改动扫描取消逻辑与状态字段，不改变 `assets.json` 结构；风险是取消发生在写入中途导致半条记录，需要明确「单文件原子写入、取消只影响下一个文件」；回滚为恢复原扫描循环。 |
| 验收标准 | 1. 200+ 文件扫描中点停止，2 秒内 `isScanning=false`<br>2. 进度停止增长，已完成资产数量正确<br>3. 停止后立即再次扫描可正常开始<br>4. `assets.json` 可正常解析，无半写记录 |
| 优先级依据 | 影响大库用户；频率中等；替代路径是等待完成；不造成数据损坏，故按优化跟踪。若后续确认取消会导致数据不一致或无法再次扫描，应升级为 Bug（S2）。 |
| 是否阻塞发版 | 否 |
| 关联用例 | TC-GAL-006、TC-GAL-007 |
| 关联问题 | 无 |
| 状态 | 新建 |
| 记录人 / 日期 | Agent / 2026-11-04 |

**实现建议**

- 将取消标志统一为扫描任务实例上的可查询状态，`stop_scan` 通过同一个控制器写入。
- 扫描循环每个文件开始前检查取消标志；当前文件完成后退出，保证不产生半条记录。
- 前端轮询以「状态接口」为准，不仅看本地 `isStoppingScan`。
