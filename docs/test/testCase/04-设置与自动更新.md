# 04 设置与自动更新测试用例

## 1. 模块信息与前置

| 项 | 内容 |
|---|---|
| 页面入口 | 侧边栏「设置」「关于」 |
| 前端核心 | `pages/SystemSettingsPage.tsx`、`stores/useSettingsStore.ts`、`stores/useAppUpdateStore.ts` |
| 后端核心 | `src/core/config/`、`src/core/updater/`、`bridge/controllers` 相关设置方法 |
| 配置路径 | 开发：`<项目根>/backend/config`；打包：`<exe 同级>/config`（JSON） |
| 保存方式 | 加锁写临时文件 → 校验 → 重命名；版本升级时备份并迁移，失败回滚 |
| 更新器 | `ComfyNexusUpdater_v1.0.exe`（独立 exe） |
| 公共前置 | **必须在桌面应用内测试**；纯浏览器 dev 模式设置只改内存，不落盘（不能作为持久化结论） |

### TC-SET-011 下载更新：进度、续传与 SHA256 校验

| 字段 | 内容 |
|---|---|
| 优先级 | P1（打包产物与桩更新源就绪后升 P0） |
| 设计方法 | 场景法 + 异常容错 |
| 前置条件 | 测试通道提供约 50MB 更新包；准备一份 hash 正确、一份 hash 错误的元数据；网络层可用桩替换（官方通道域名不可直接指向本机） |
| 测试数据 | 正确/错误 `file_hash`；中途关闭网络 |
| 操作步骤 | 1. 下载正确包，观察进度<br>2. 中途断开网络再恢复<br>3. 用错误 hash 重试<br>4. 检查本地包与临时文件 |
| 预期结果 | 1. 进度百分比单调递增，界面可取消<br>2. 断开后可续传或重新下载，不产生损坏包<br>3. hash 不匹配时拒绝应用更新并给出错误<br>4. 失败后清理或标记坏包，不反复使用 |
| 可自动化程度 | 半自动 |
| 关联风险 | R-SET-02（官方通道缺合法 hash 即拒绝；开发通道跳过校验） |
