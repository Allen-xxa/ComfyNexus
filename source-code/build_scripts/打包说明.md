# ComfyNexus 打包说明

## 快速打包脚本使用指南

### 基本用法

```powershell
# 在 source-code/ 目录下运行（quick_build.ps1 位于 source-code/，不在仓库根）
cd source-code
.\quick_build.ps1
```

脚本会依次询问（以下提示与分支均取自 `quick_build.ps1` 源码）：
1. **打包模式**: `[1]` 生产模式（隐藏控制台，默认）/ `[2]` 调试模式（显示控制台）
2. **前端构建**: `[1]` **跳过**前端构建（默认！）/ `[2]` 完整构建前端
3. **版本号**: 直接回车从 `source-code/comfy_nexus_version.py` 的 `__version__` 读取，或手动输入

> ⚠️ **默认值陷阱**：第 2 问直接回车等于"跳过前端构建"，会复用上次生成的 `source-code/dist/`。
> 前端有改动或首次打包时**必须输入 `2`**。（`quick_build.ps1:60-62`、`:67` 的默认分支是 `$SkipFrontend = $true`。）

> **注意**：`quick_build.ps1` 自身**不接受任何命令行参数**（`Get-Command .\quick_build.ps1` 的 `Parameters` 数量为 0），只能交互式运行；需要非交互构建请调用 `build_scripts/快速构建.ps1 -Version ... -SkipFrontend -ShowConsole`（三个参数见其 `param` 块）或根目录的 `build.ps1`（支持 `-Version/-SkipFrontend/-SkipClean/-SkipTests/-VerboseOutput`）。
> 版本号唯一来源是 `comfy_nexus_version.py`（当前 `__version__ = "v1.2.5"`），读取逻辑见 `build_scripts/构建工具库.ps1:93-117`，文件缺失时回落 `"1.0.0"`；**仓库中不存在名为 `VERSION` 的文件**。

### 打包模式说明

#### 🟢 生产模式（默认）
- **特点**: 隐藏控制台窗口
- **适用场景**: 正式发布给用户
- **优点**: 界面更加专业美观，用户体验好
- **缺点**: 无法看到控制台输出，不便于调试
- **选择**: 在交互式界面中输入 `1`

#### 🟡 调试模式
- **特点**: 显示控制台窗口
- **适用场景**: 开发测试、问题排查
- **优点**: 可以看到所有日志和错误信息
- **缺点**: 会显示黑色控制台窗口
- **选择**: 在交互式界面中输入 `2`

### 常见使用场景

#### 场景 1: 日常开发测试
在 `source-code/` 运行 `.\quick_build.ps1`，然后：
1. 选择 `[2]` 调试模式
2. 选择 `[1]` 跳过前端构建（如果前端未改动；直接回车即是此项）
3. 直接回车使用默认版本号（`v1.2.5`，来自 `comfy_nexus_version.py`）

#### 场景 2: 正式发布
在 `source-code/` 运行 `.\quick_build.ps1`，然后：
1. 选择 `[1]` 生产模式（默认）
2. **选择 `[2]` 完整构建前端**（不能回车，回车是跳过）
3. 输入版本号，例如 `1.0.2`

#### 场景 3: 快速重新打包（前端未改动）
1. 选择 `[1]` 生产模式
2. 选择 `[1]` 跳过前端构建（默认）
3. 直接回车使用默认版本号

#### 场景 4: 调试打包问题
1. 选择 `[2]` 调试模式
2. 选择 `[1]` 跳过前端构建（默认）
3. 直接回车使用默认版本号

### 技术细节

#### Spec 文件
- **build_exe.spec**: 生产模式配置（`console=False`，见 `:281`）
- **build_exe_debug.spec**: 调试模式配置（`console=True`，见 `:281`）
- **backend/updater/updater.spec**: 更新器 exe，由 `build_scripts/构建.ps1:300` 单独调用
- **ComfyNexus.spec**（`console=True`）：存在于 `source-code/`，但在 `build_scripts/*.ps1` 中**没有任何引用**（`grep -rn "\.spec" build_scripts/` 实测），不要误当作发布配置

#### 自动选择逻辑
`build_scripts/构建.ps1:255-258` 根据 `-ShowConsole` 参数自动选择对应的 spec 文件：
```powershell
if ($ShowConsole) {
    $SpecFile = "build_exe_debug.spec"
} else {
    $SpecFile = "build_exe.spec"
}
```

> **已知缺口**：`build.ps1` 的 `param` 块只透传 `-Version/-SkipFrontend/-SkipClean/-SkipTests/-VerboseOutput`，**没有 `-ShowConsole`**；需要调试版 exe 时请直接调用 `build_scripts/构建.ps1 -ShowConsole` 或使用 `quick_build.ps1` 交互选择 `[2]`。

### 构建产物管理

- `source-code/dist/`（前端构建输出）、`source-code/build/` 与 `source-code/backend/{build,dist}/`（PyInstaller 产物）、`source-code/frontend/coverage/`、`source-code/frontend/tsconfig.tsbuildinfo` 都是生成物，**不纳入版本控制**。
- 打包脚本会重新构建前端并生成 `source-code/dist/`（`构建.ps1:35` 的 `$TempDistDir = <source-code>/dist`，与 `vite.config.ts:17` 的 `outDir: '../dist'` 对应）；最终发布包输出在 `source-code/build_scripts/打包产物_<版本号>/`
- 克隆仓库后首次打包：`quick_build.ps1` 第 2 问必须输入 `[2]`（完整构建前端），或先手动执行 `cd source-code/frontend && npm ci && npm run build`
- 如果历史提交中已跟踪构建产物，用 `git rm -r --cached <路径>` 清理（保留本地文件），不要用不带 `--cached` 的 `git rm`。
- 开发模式启动后端前同样需要先构建前端，否则找不到 `source-code/dist/index.html`。

### 注意事项

1. **首次打包**: 需要完整构建前端，交互提示中选择 `[2]`（否/完整构建）；直接回车是"跳过前端构建"
2. **版本号**: 建议在正式发布时明确指定版本号
3. **调试模式**: 仅用于开发测试，不要发布给用户
4. **虚拟环境（重要，实测缺口）**: `build_scripts/构建.ps1:32,36` 把 venv 固定在 `source-code/.venv`
   （`$ProjectRoot = Split-Path -Parent $PSScriptRoot` → `source-code/`），并在 `:121-125` 检查，缺失时直接报
   `Python 虚拟环境不存在: ...\source-code\.venv`。而本仓库的开发 venv 实际在 `source-code/backend/.venv`，
   `source-code/.venv` 目前**不存在**——因此走 `build.ps1`/`构建.ps1` 全量构建前，需要在 `source-code/` 下另建 `.venv`
   （或修改脚本路径，属功能变更，需另行确认）。调用链 `quick_build.ps1` → `build_scripts/快速构建.ps1:45-47` → `构建.ps1`
   同样受此约束。
5. **依赖检查**: `构建.ps1:51 Test-Command` 检查 `node`/`npm`，`:130` 用 venv 内 `pip show pyinstaller` 检查 PyInstaller
6. **MinGit 不参与打包**: `build_exe.spec` 与 `build_scripts/*.ps1` 中都没有 MinGit 相关逻辑，用户侧 Git 由应用首次启动的 Bootstrap 窗口下载或复用系统 Git
7. **`构建.ps1` 的测试步骤指向不存在的文件**: `:177` 执行 `backend\tests\test_utf8_encoding.py`，该文件在仓库中不存在
   （`ls` 实测）。外层有 try/catch，仅输出"测试执行出错"警告并继续构建，不会中断打包；但这一步实际没有做任何验证。
   `quick_build.ps1` 走的 `快速构建.ps1` 恒传 `-SkipTests`，因此连这一步都会被跳过

### 故障排查

#### 问题 1: 打包失败
`quick_build.ps1` 没有参数，调试模式要在交互提示里输入 `2`；若要一次性命令式调用，直接用底层脚本：
```powershell
# 调试模式（显示控制台）+ 跳过前端
cd source-code
.\build_scripts\快速构建.ps1 -ShowConsole -SkipFrontend

# 或走 build.ps1（它把参数透传给 build_scripts/构建.ps1）
.\build.ps1 -VerboseOutput
```

#### 问题 2: 前端构建失败
```powershell
# 手动构建前端
cd source-code/frontend
npm ci
npm run build
cd ..

# 然后跳过前端构建（quick_build.ps1 里对"是否跳过前端"输入 Y）
.\build_scripts\快速构建.ps1 -SkipFrontend
```

#### 问题 3: PyInstaller 未安装
在构建脚本期望的 venv（`source-code/.venv`）里安装：
```powershell
cd source-code
python -m venv .venv              # 若不存在；需 Python 3.12.x
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
pip install pyinstaller
```

### 相关脚本

在 `source-code/` 下的实际文件清单（`ls *.ps1 build_scripts/*.ps1` 实测）：

- `build.ps1`: 完整构建入口（透传参数给 `build_scripts/构建.ps1`；**不透传 `-ShowConsole`**）
- `quick_build.ps1`: 交互式快速打包入口（无参数）
- `build_scripts/构建.ps1`: 完整构建实现（内部流程标注 `步骤 N/8`，实测出现 1/8–7/8 标签；依赖检查、PyInstaller 调用都在此）
- `build_scripts/快速构建.ps1`: 快速构建实现（恒传 `-SkipTests -SkipClean`）
- `build_scripts/构建前端.ps1` / `构建后端.ps1` / `构建runtime包.ps1` / `创建发布包.ps1` / `验证构建.ps1`: **独立手动脚本**。
  `构建.ps1` 不调用它们（`grep -n "创建发布包\|验证构建\|构建前端\|构建后端" 构建.ps1` 只命中注释与自有步骤标题），
  而是直接内联实现各步骤并复用 `构建工具库.ps1` 的函数（如 `:320` 的创建发布包函数）
- `build_scripts/构建工具库.ps1`: 公共函数库（含 `Get-ProjectVersion:93-117`、`Test-Command`）
- `pre_build_check.py`: `构建.ps1:89` 调用构建前置检查
- `backend/scripts/diagnose_system.py` + `backend/scripts/ComfyNexusDiag.spec`: 运行环境检测工具（exe 为生成物，不入库）
